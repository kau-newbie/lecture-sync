# lecture-sync: 강의자료 동기화

새 강의자료를 감지해 정리 문서(장별 보충본과 퀴즈, 또는 예시 위주 예제집) 작성, 지식 그래프 갱신, 알림 메일 발송까지 진행한다.

## 원칙

- **과목마다 따로 만든다.** 그래프, 보충본과 퀴즈 데이터, 기준 기록, 아티팩트 URL은 모두 과목 폴더의 `.lecture-sync/` 안에 있다. 다른 과목의 그래프를 복사하거나 참고해서 배치를 따라 하지 않는다. 과목마다 개념 구조가 다르므로, 그 과목 자료에 맞게 그룹, 묶음, 배치를 새로 설계한다.
- **자료에서 확인한 것만 쓴다.** 슬라이드에서 추출되지 않은 그림, 수식, 개체는 추정으로 채우지 않는다. 확인하지 못했다고 보충본과 메일에 적는다.
- **사용자의 문체 지침을 따른다.** 사용자가 문체를 지정했으면(예: 쉽고 공식적인 문체) 보충본, 퀴즈, 메일에도 같이 적용한다.
- **비밀번호를 출력하거나 파일에 적지 않는다.**
- 이 스킬 폴더 기준 `../../scripts/`에 스크립트가 있다. 아래에서는 `$SCRIPTS`라고 부른다. 찾지 못하면 `find ~/.claude/plugins -name detect.py -path "*lecture-sync*"`로 찾는다.
- 스크립트는 `python3`로 직접 부르지 않고 `bash "$SCRIPTS/py.sh"`로 실행한다. `py.sh`는 운영체제마다 다른 Python 명령(`python3`, `python`, `py -3`) 중 동작하는 것을 찾고, 출력을 UTF-8로 맞춘다. Windows에서도 같은 명령을 쓴다.

## 절차

### 1. 과목 폴더와 설정 확인

과목 폴더는 `.lecture-sync.json`이 있는 폴더다. 현재 폴더에서 위로 올라가며 찾는다. 설정 항목은 다음과 같다.

| 항목 | 뜻 |
|---|---|
| `course` | 과목 이름 |
| `notify_to` | 알림 메일을 받을 주소 |
| `extensions` | 강의자료 확장자. 기본값은 `.pptx`, `.ppt`, `.pdf` |
| `style` | 정리 방식. `"slides"`(장별 보충본과 퀴즈) 또는 `"examples"`(예시 위주 예제집). 없으면 2단계에서 묻는다 |
| `transcript` | 강의 영상 스크립트 사용 여부. `{"enabled": true, "browser": "chrome"}`처럼 쓴다. `browser`는 `"chrome"` 또는 `"edge"`. 쓰지 않으면 `{"enabled": false}`. 없으면 2단계에서 묻는다 |

설정 파일이 없으면 사용자에게 알리고 멈춘다. 만드는 방법은 `README.md`에 있다.

### 2. 변경 확인

```bash
bash "$SCRIPTS/py.sh" "$SCRIPTS/detect.py" --root "<과목 폴더>" --list
```

`new`와 `modified` 목록, 설정값 `style`, `transcript`가 나온다. 둘 다 비어 있으면 "새 자료가 없다"고 알리고 끝낸다. 목록이 있으면 처리할 파일을 사용자에게 한 줄로 알린 뒤 진행한다.

**처음 실행(`first_run`이 true):** 기존 파일을 모두 새 자료로 보고 있는 상태다. 아래 세 가지를 한 번에 묻는다(AskUserQuestion 도구가 있으면 질문 하나에 한 항목씩 넣어 한 번에 묻는다).

1. 기존 자료 처리
   - 모두 정리한다: 아래 절차를 모든 파일에 진행한다. 파일이 많으면 시간이 오래 걸린다고 먼저 알린다.
   - 처리한 것으로 기록만 한다: 이후에 추가되는 파일만 처리한다. 2, 3번 답을 저장한 뒤 다음을 실행하고 끝낸다.

```bash
bash "$SCRIPTS/py.sh" "$SCRIPTS/detect.py" --root "<과목 폴더>" --baseline
```

2. 정리 방식 (`style`)
   - 장별 보충본과 퀴즈(`slides`): 슬라이드마다 원문, 번역, 배경, 상세 설명, 예시를 담는다. 강의자료를 순서대로 복습할 때 알맞다.
   - 예시 위주 예제집(`examples`): 강의자료의 순서를 따르지 않고, 배운 내용을 쓰는 실제 예시를 여러 개 만들어 설명한다. 코딩·설계 과목은 구조 그림, 상태도, 전체 코드로, 이론·계산 과목은 실제 상황 문제와 단계별 풀이로 쓴다.
   - 추천을 붙인다. 3단계처럼 자료 몇 개의 텍스트를 먼저 훑어보고, 코드, HDL, 회로, 알고리즘, 설계 과제가 많으면 예제집을, 그렇지 않으면 장별 보충본을 첫 번째 보기로 두고 "(추천)"을 붙인다. 추천 이유를 한 줄 적는다.
3. 강의 영상 스크립트 (`transcript`)
   - 사용하지 않는다.
   - Chrome에서 가져온다 / Edge에서 가져온다: 4단계 전에 "강의 영상 스크립트 수집" 절차를 진행한다. Claude in Chrome 확장 프로그램이 그 브라우저에 설치되어 있어야 한다고 함께 알린다.

답은 `.lecture-sync.json`에 저장한다. 다른 항목은 그대로 두고 `style`, `transcript`만 더한다. 예: `"style": "examples", "transcript": {"enabled": true, "browser": "chrome"}`.

**처음 실행이 아닌데 `style`이나 `transcript`가 null인 경우:** 위 2, 3번 중 정하지 않은 것만 묻고 저장한다. 사용자가 나중에 방식을 바꾸고 싶다고 하면 설정 파일의 값을 고친다. 방식을 바꿔도 이미 만든 문서는 그대로 두고, 새 자료부터 새 방식으로 정리한다. 기존 자료도 새 방식으로 다시 정리할지는 사용자에게 묻는다.

### 3. 슬라이드 텍스트 추출

파일마다 실행한다.

```bash
bash "$SCRIPTS/py.sh" "$SCRIPTS/extract_slides.py" "<파일>"
```

- `.pptx`, `.pdf`는 장별 텍스트가 나온다. 출력의 "텍스트로 추출되지 않음" 줄은 그림, 수식 등이 있다는 뜻이다. 기록해 둔다.
- `.ppt`는 읽을 수 없다(종료 코드 2). 이 파일은 보충본, 퀴즈, 그래프에 반영하지 않는다. 메일에 ".pptx로 저장해 달라"고 적는다.
- 슬라이드에 글자 없이 그림만 있는 장은 텍스트로 확인할 수 없다. 페이지를 이미지로 바꿔 볼 수 있는 환경이면(`pdftoppm` 등) 이미지를 읽어 확인하고, 확인한 방법을 적는다. 볼 수 없으면 "확인하지 못한 부분"으로 둔다.
- 감지한 파일 중 본인 과제물(보고서 등)처럼 강의자료가 아닌 파일이 있으면 정리 대상인지 사용자에게 먼저 묻는다. 정리하지 않기로 하면 7단계에서 처리 완료로 기록만 한다.

### 3-1. 강의 영상 스크립트 수집 (`transcript.enabled`가 true일 때만)

강의 사이트가 보여 주는 자막이나 스크립트 텍스트만 읽는다. 동영상 파일을 내려받지 않고, 음성을 직접 텍스트로 바꾸지 않으며, 다운로드 방지나 로그인 같은 보호 장치를 우회하지 않는다.

1. `anthropic-skills:chrome-browser` 스킬이 있으면 먼저 불러오고, Claude in Chrome 도구(`mcp__claude-in-chrome__*`)를 쓴다. 도구가 없거나 확장 프로그램이 연결되지 않으면 사용자에게 알리고 이 단계를 건너뛴다. 메일에 "스크립트를 가져오지 못했다"고 적는다.
   - `browser`가 `"edge"`이면 Edge에 Claude in Chrome 확장 프로그램이 설치되어 연결되어 있어야 한다. 연결되지 않으면 Chrome으로 진행할지 사용자에게 묻는다.
2. 강의자료마다 해당 강의 영상 페이지를 찾는다. 사용자에게 강의 사이트 주소나 영상 페이지 주소를 묻는다. 로그인은 사용자가 브라우저에서 직접 한다. 비밀번호를 대신 입력하거나 저장하지 않는다.
3. 페이지의 자막·스크립트 패널, 자막 텍스트 등 화면에 제공되는 텍스트를 읽는다. 자막이 없으면 "자막 없음"으로 기록하고 넘어간다.
4. 읽은 텍스트를 `<과목 폴더>/.lecture-sync/transcripts/<id>.txt`에 저장한다. 첫 줄들에 영상 제목, 페이지 주소, 가져온 날짜를 적는다. `<id>`는 4단계의 강의자료 id와 같게 한다.
5. 스크립트는 음성 인식 결과일 수 있어 용어가 틀릴 수 있다. 슬라이드와 맞춰 확인되는 내용만 정리에 쓰고, 슬라이드와 다르게 말한 부분은 "강의에서는 ~라고 설명했다"처럼 출처를 밝혀 쓴다.
6. 정리에 넣는 곳: 장별 보충본은 장마다 `lecture` 칸과 `meta.json`의 `transcript`(출처)에, 예제집은 예제의 `lecture` 칸과 `meta.json`의 `transcript`에 쓴다.

### 4. 정리 문서 작성

`style`에 따라 4-A 또는 4-B 중 하나를 진행한다.

### 4-A. 장별 보충본과 퀴즈 (`style`이 `"slides"`)

파일마다 아티팩트 두 개를 만든다.

- **보충본**: 슬라이드마다 원문, 번역, 배경, 상세 설명, 예시와 풀이를 담는다. 슬라이드가 많아도 한 페이지로 만든다. 페이지에 목차가 있다.
- **퀴즈**: 보충본 내용을 잘 배웠는지 확인하는 문제와 해설을 담는다.

데이터는 `<과목 폴더>/.lecture-sync/notes/<id>/`에 JSON으로 쓴다. `<id>`는 `w3-rtsensor3`처럼 주차와 파일 이름으로 짧게 정한다. 파일 형식과 본문 표기법은 `$SCRIPTS/build_notes.py`의 맨 위 설명에 있다.

| 파일 | 내용 |
|---|---|
| `meta.json` | 원본 파일, 주차, 주제, 요약, 주차 목표, 소목표, 먼저 알아야 할 내용, 핵심 공식, 확인하지 못한 부분, 아티팩트 URL |
| `slides-01.json`, `slides-02.json`, ... | 장별 내용. 한 파일에 10장 정도씩 나눠 쓴다. 빌드할 때 합친다 |
| `quiz.json` | 퀴즈 문제 |

**강의 흐름 (주차 목표, 소목표, 장별 결론)**

장별 내용을 쓰기 전에 강의 전체의 흐름을 먼저 정한다. 보충본의 목차, 흐름 상자, 소목표 카드가 이 데이터로 만들어진다.

1. `goal`: 강의 전체가 답하는 질문을 한두 문장으로 쓴다. 슬라이드에 개요나 "two questions" 같은 장이 있으면 그 장을 근거로 삼고 장 번호를 적는다.
2. `sections`: 장을 3~6개의 소목표로 묶는다. 각 소목표에 `id`(A, B, ...), `title`, 장 범위(`from`, `to`), `question`(이 부분이 답하는 질문), `conclusion`(이 부분의 결론)을 쓴다. 범위는 1장부터 마지막 장까지 빈틈과 겹침 없이 이어져야 한다.
3. 장마다 `conclusion`에 이 장의 결론을 한두 문장으로 쓴다. 이 장에서 알게 되는 사실이나 계산 결과를 쓰고, 장 제목을 반복하지 않는다. `brief` 장은 비워도 된다.
4. 결론도 슬라이드에서 확인한 내용으로만 쓴다. 추출되지 않은 내용을 일반적인 논리로 정리했다면 그렇게 적는다.

**장마다 쓸 내용**

1. `original`: 추출한 슬라이드 원문을 그대로 옮긴다. 줄바꿈만 정리한다.
2. `translation`: 원문 전체를 사용자의 언어로 번역한다. 요약하지 않는다. 전문 용어는 원어를 그대로 쓰고, 일반적으로 쓰는 번역어가 없으면 번역어를 새로 만들지 않는다.
3. `background`: 이 슬라이드가 왜 나오는지, 이해하는 데 필요한 앞 내용(이전 장, 이전 주차)을 설명한다.
4. `detail`: 슬라이드 내용을 처음 배우는 사람이 따라올 수 있도록 단계별로 설명한다. 정의, 조건, 이유, 자주 헷갈리는 점을 적는다. 슬라이드에 적힌 것보다 자세하게 쓴다.
5. `lecture`(선택): 강의 영상 스크립트에서 이 장을 설명한 내용. 3-1단계를 진행했을 때만 쓴다.
6. `example`(선택): 슬라이드의 예시나 문제를 풀이한다. 숫자는 직접 계산해서 검증한다(`bash "$SCRIPTS/py.sh" -c "..."`로 계산해도 된다). 슬라이드에 예시가 없어도 개념 이해에 필요하면 짧은 예시를 만들고, 만든 예시라고 적는다.
7. `unverified`(선택): 이 장에서 텍스트로 추출되지 않은 그림, 수식 개체. 추정으로 채우지 않는다. 표준 수식으로 설명했다면 그렇게 적는다.
8. 표지, 목차, 빈 장은 `brief: true`로 두고 원문과 번역만 쓴다.

**퀴즈 작성 기준**

- 강의자료 하나에 10~20문제를 낸다. 슬라이드가 적으면 줄인다.
- 유형을 섞는다: `mc`(객관식), `tf`(O/X), `calc`(계산), `short`(서술). 계산 문제가 가능한 자료에는 반드시 넣는다.
- 모든 문제는 슬라이드에서 확인한 내용으로만 낸다. `slides`에 근거 장 번호를 적는다.
- `explain`에는 정답인 이유와, 오답 보기가 왜 틀렸는지를 적는다. 계산 문제는 풀이 과정을 적고 숫자를 직접 검증한다.
- 객관식 정답 위치가 한쪽으로 몰리지 않게 한다.

**검사와 발행**

```bash
bash "$SCRIPTS/py.sh" "$SCRIPTS/build_notes.py" "<notes 폴더>" --check
bash "$SCRIPTS/py.sh" "$SCRIPTS/build_notes.py" "<notes 폴더>" --kind notes --out "<notes 폴더>/notes.html"
bash "$SCRIPTS/py.sh" "$SCRIPTS/build_notes.py" "<notes 폴더>" --kind quiz --out "<notes 폴더>/quiz.html"
```

`--check`가 "문제 없음"을 출력할 때까지 고친다. 발행 순서는 다음과 같다. 두 페이지가 서로를 링크하기 때문이다.

1. 보충본을 발행하고 URL을 `meta.json`의 `notes_url`에 저장한다.
2. 퀴즈를 다시 만들어 발행하고 URL을 `quiz_url`에 저장한다. 퀴즈 해설의 장 번호가 보충본의 해당 장으로 연결된다.
3. 보충본을 다시 만들어 같은 URL로 다시 발행한다. 퀴즈 링크가 들어간다.

`graph_url`에는 그래프 아티팩트 URL을 넣는다(5단계에서 새로 만들었다면 5단계 뒤에 넣고 다시 만든다). 이미 URL이 있으면 그 URL로 다시 발행한다. 아티팩트 도구가 없는 환경이면 `notes.html`, `quiz.html` 경로를 알린다.

`modified` 파일은 기존 notes 폴더의 바뀐 장과 관련 문제만 고치고 같은 URL로 다시 발행한다. 무엇을 고쳤는지 메일에 적는다.

### 4-B. 예시 위주 예제집 (`style`이 `"examples"`)

과목마다 예제집 아티팩트 하나를 만들고, 새 자료가 들어올 때마다 예제를 더해 같은 URL로 다시 발행한다. 퀴즈는 만들지 않는다.

데이터는 `<과목 폴더>/.lecture-sync/examples/`에 둔다. 파일 형식, 그림(SVG) 규칙, 본문 표기법은 `$SCRIPTS/build_examples.py`의 맨 위 설명에 있다.

| 파일 | 내용 |
|---|---|
| `meta.json` | 제목, 과목, 다룬 범위, 도입, 근거 자료, 공통 용어, 예제 묶음 순서, 확인하지 못한 부분, 아티팩트 URL |
| `ex-01.json`, `ex-02.json`, ... | 예제 하나씩. 파일 이름 순서가 예제 순서다 |
| `fig/*.svg` | 구조 그림, 상태도, 파형, 그래프 |
| `code/*` | 예제 코드 파일 (코딩·설계 과목) |

**범위 정하기**

1. 이번까지 처리한 자료가 다루는 주차를 범위로 한다. 1주차 개요 자료에 주차별 일정표가 있으면 그 표로 주차별 주제를 확인한다.
2. 예제에는 그 범위에서 배운 개념과 문법만 쓴다. 뒤 주차의 개념이 꼭 필요하면 쓰되 `preview`에 "N주차 내용 미리보기"라고 적는다.
3. 새 자료가 들어오면 기존 예제는 두고 새 범위의 예제를 뒤에 더한다. 기존 예제의 `id`와 파일 이름은 바꾸지 않는다. 그래프와 메일의 링크가 `id`를 쓰기 때문이다. `meta.json`의 `scope`와 `sources`를 고친다.

**예제 고르기**

- 처음 만들 때는 10~16개, 이후 자료 하나마다 2~5개를 더한다. 쉬운 것에서 어려운 것 순서로 두고, `parts`로 묶는다.
- 서로 다른 실제 시스템이나 상황을 고른다. 같은 개념을 이름만 바꿔 반복하지 않는다.
- 마지막 쪽에는 앞 예제들을 조합하는 통합 예제를 둔다.
- 코딩·설계 과목: 동작하는 시스템을 만든다(예: 디코더, ALU, 카운터, 상태머신, 통신 모듈). 이론·계산 과목: 실제 상황을 가정한 문제를 만든다(예: 주어진 작업 집합의 스케줄 가능성 판정).

**예제마다 쓸 내용**

1. `background`: 이 시스템이나 문제가 실제로 어디에 쓰이는지, 어떤 개념을 쓰는지 설명한다.
2. `terms`: 이 예제에 처음 나오는 용어. 번역어를 만들지 않는다.
3. `figures`: 구조를 보여 주는 그림. 코딩·설계 과목은 architecture 그림(블록과 신호 연결)을 반드시 넣고, 상태머신이면 상태도를 넣는다. 그림은 이름만 적힌 상자가 아니라 신호가 어디서 어디로 가는지를 보여 주게 그린다. 화살표에 신호 이름을 적는다. `artifact-diagramming` 스킬이 있으면 먼저 불러온다.
4. `flow`: 데이터나 계산이 어떤 순서로 흘러가는지 번호 목록으로 쓴다. 입력 예시 하나를 따라가는 표를 넣으면 좋다.
5. `code`(코딩·설계 과목): 컴파일할 수 있는 전체 코드를 파일로 쓴다. 코드 안 주석은 짧게 쓴다. 컴파일러나 시뮬레이터가 있으면 실행해 확인하고, 없으면 `meta.json`의 `notice`에 "코드는 실행해 보지 않았다"고 적는다.
6. `solution`(이론·계산 과목): 단계별 풀이. 숫자는 직접 계산해서 검증한다.
7. `explain`: 코드나 풀이의 중요한 부분을 설명한다. 슬라이드의 어느 장과 연결되는지 적는다.
8. `pitfalls`(선택): 자주 하는 실수.
9. `src`: 근거 슬라이드 ("dsd_note 19~21장"처럼). 슬라이드에 없는 일반 지식(통신 규격 등)을 썼으면 그렇게 적는다.
10. `lecture`(선택): 3-1단계에서 가져온 강의 설명 중 이 예제와 관련된 내용.

**검사와 발행**

```bash
bash "$SCRIPTS/py.sh" "$SCRIPTS/build_examples.py" "<examples 폴더>" --check
bash "$SCRIPTS/py.sh" "$SCRIPTS/build_examples.py" "<examples 폴더>" --out "<examples 폴더>/examples.html"
```

`--check`가 "문제 없음"을 출력할 때까지 고친다. `meta.json`의 `url`이 있으면 그 URL로 다시 발행하고, 없으면 새로 발행해 URL을 `url`에 저장한다. `graph_url`에 그래프 URL을 넣고 다시 만들어 발행한다. 아티팩트 도구가 없는 환경이면 `examples.html` 경로를 알린다.

`modified` 파일은 그 자료에 근거한 예제만 고쳐 다시 발행한다. 무엇을 고쳤는지 메일에 적는다.

### 5. 지식 그래프 갱신

그래프 데이터는 `<과목 폴더>/.lecture-sync/graph.json`이다. 형식은 `$SCRIPTS/build_graph.py`의 맨 위 설명에 있다. 파일이 없으면 이 과목의 첫 그래프로 새로 만든다.

**항목과 연결을 추가하는 방법**

1. 새 자료의 개념을 항목(node)으로 만든다. 같은 개념이 이미 있으면 새 항목을 만들지 않는다. 기존 항목의 `weeks`와 `desc`를 고치고, 새 연결만 추가한다.
2. 주차와 관계없이 관련 있는 항목끼리 연결한다. 트리로 만들지 않는다. 순환 연결도 허용한다.
   - `t: "u"`: 앞의 내용이 뒤의 내용에 쓰이거나 적용된다. 화살표로 그린다.
   - `t: "c"`: 서로 비교되거나 대조된다. 점선으로 그린다.
   - `t: "h"`: 분류의 하위 항목이다. 선으로 그린다.
   - 연결마다 짧은 `label`(관계 설명)을 적는다.
3. 연결의 근거를 구분한다. 이번에 슬라이드에서 직접 확인한 연결만 `src`에 "N주차 M장"으로 적는다. 나머지는 `src`를 비운다. `src`는 페이지에 표시되지 않고 `graph.json`에만 남는다. 메일에 근거를 적을 때 쓴다.
4. 그룹(`groups`)은 색 구분이다. 최대 6개다. 주차가 6개를 넘으면 인접한 주차를 묶는다(예: "5~6주차"). `special: true`인 그룹은 id 1 하나만 쓴다. 첫 주차의 개론 내용처럼 나중 내용과 구분해서 보여 주고 싶은 그룹에 쓴다. 필요 없으면 쓰지 않는다.
5. 좌표를 정한다. 빈 곳에 새 항목을 놓고, 관련 항목 근처에 둔다. 묶음(`hulls`)의 크기도 맞춘다.
6. 다음을 실행해 겹침이 0건이 될 때까지 좌표와 경로(`sides`, `pts`)를 고친다.

```bash
bash "$SCRIPTS/py.sh" "$SCRIPTS/build_graph.py" "<과목 폴더>/.lecture-sync/graph.json" --check
```

7. `style`이 `"examples"`이면 `refs`에 그 개념을 쓰는 예제 링크(`<예제집 url>#<예제 id>`)를 단다. 아래 보충본 링크 규칙은 `"slides"`일 때 쓴다.
   보충본이 있는 항목에는 `refs`에 보충본의 해당 장 링크(`<notes_url>#s<장 번호>`)를 단다. 여러 장에 걸친 개념은 소목표 카드(`<notes_url>#sec<소목표 id>`)로 연결한다. 한 항목이 여러 주차에 걸치면 주차마다 링크를 하나씩 단다. 보충본 URL이 아직 없으면 4단계 발행 뒤에 단다.
8. `changelog`에 이번 수정 내용을 한 줄로 더한다. `checks`에는 확인하지 못한 부분(그림, 수식, 읽을 수 없는 파일)을 적는다.
9. HTML을 만들고 발행한다.

```bash
bash "$SCRIPTS/py.sh" "$SCRIPTS/build_graph.py" "<과목 폴더>/.lecture-sync/graph.json" --out "<과목 폴더>/.lecture-sync/graph.html"
```

- `artifact_url`이 있으면 그 URL로 다시 발행한다(`url` 지정). 없으면 새로 발행하고, 나온 URL을 `graph.json`의 `artifact_url`에 저장한다.
- 아티팩트 도구가 없는 환경이면 `graph.html` 파일 경로를 알리고 다음 단계로 넘어간다.

### 6. 알림 메일

수신 주소는 `notify_to`다. 없으면 메일을 보내지 않고 사용자에게 알린다. 본문을 임시 파일에 쓰고 보낸다.

```bash
bash "$SCRIPTS/py.sh" "$SCRIPTS/notify.py" --to "<notify_to>" --subject "[강의 정리] <과목> 자료 <N>건 반영" --body-file "<본문 파일>"
```

본문에 담을 내용은 다음과 같다.

1. 정리 문서 링크(`slides`: 파일마다 보충본과 퀴즈, `examples`: 예제집), 지식 그래프 링크
2. 처리한 파일 목록(신규, 수정)과 파일마다 장 수, 퀴즈 문제 수(`slides`) 또는 이번에 더한 예제 목록(`examples`)
3. 정리 문서에서 다룬 주요 내용 몇 줄, 강의 영상 스크립트를 가져왔는지
4. 그래프에서 바뀐 점: 추가한 항목, 추가한 연결, 고친 항목
5. 확인하지 못한 부분과 사용자가 해야 할 일(예: `.ppt`를 `.pptx`로 저장)

`GMAIL_APP_PASSWORD`가 없으면 발송하지 않고 종료 코드 3으로 끝난다. 이때 본문을 사용자에게 보여 주고, 앱 비밀번호 등록 방법을 안내한다.

### 7. 처리 완료 기록

정리 문서(보충본과 퀴즈, 또는 예제집)와 그래프 반영에 성공한 파일만 기록한다. 강의 영상 스크립트를 가져오지 못한 것은 실패로 보지 않는다. 실패한 파일은 기록하지 않아서 다음 세션에 다시 감지된다.

```bash
bash "$SCRIPTS/py.sh" "$SCRIPTS/detect.py" --root "<과목 폴더>" --commit "<상대 경로>" ...
```

`.ppt`는 안내 메일을 보낸 뒤 기록한다. `.pptx`로 저장한 파일은 내용이 달라서 새 파일로 다시 감지된다.

### 8. 폴더 안내 문서 갱신

과목 폴더에 `CLAUDE.md`가 있고 주차별 흐름 목록이 있으면, 새 주차 내용을 한 줄로 더한다.

### 9. 사용자에게 보고

다음을 짧게 알린다: 처리한 파일, 정리 문서 링크(보충본과 퀴즈, 또는 예제집), 그래프 링크, 강의 영상 스크립트 반영 여부, 메일 발송 여부, 확인하지 못한 부분.
